# Native build readiness

Checked 24 October 2026. Flutter 3.41.9 / Dart 3.11.5 and Xcode 27.1 are available. iOS simulator SDKs and runtimes are installed. CocoaPods is missing; however, the app’s only iOS plugin includes a Swift Package manifest, so Flutter’s experimental opt-in SPM path may avoid a CocoaPods installation. The Xcode project has not yet been migrated or verified on that path. Android command-line and platform tools are present, but a complete Android SDK with API 36 and its build dependencies is not installed. The local JDK 17 is usable when its `JAVA_HOME` is set; the current project SDK path points only to platform-tools.

The Android and iOS project files are present; no native source packaging blocker was found. No build, SDK package installation, app installation, simulator boot, signing, or device action was performed. During an Android CLI help probe, the executable unexpectedly bootstrapped/downloaded its command-line CLI; no SDK components or app packages were installed and no terms were explicitly accepted. The minimum Android path is a complete SDK setup followed by a debug APK build. The iOS path to investigate first is opt-in SPM; if that fails, use locally scoped CocoaPods setup and resolve the Flutter plugin pods. Neither debug route creates a production-signed release or completes physical-device acceptance.

Issue 4 remains open for device behavior, accessibility, signing/update continuity, and long-run power/display checks. A debug artifact cannot replace those owner/device gates. A detailed host-only inventory is retained in the local workspace and is not part of this public evidence note.
