Setup & support

A few minutes
to make it yours.

Start with the browser preview or build from the versioned Flutter source. Native production binaries are not available in this preview.

Try the display

  1. Open the browser preview. It is a real Flutter web build, with native screen controls unavailable.
  2. Choose a preset in Layouts. Change clock face, theme and 12/24-hour time in Settings.
  3. Keep weather off, or explicitly enable it and choose a city. Check the timestamp before relying on a condition.
  4. Use Quiet display to hide navigation. The visible exit button restores controls.

Build from source

The recorded toolchain is Flutter 3.41.9 and Dart 3.11.5. The source is MIT; resolved packages carry their own notices.

git clone https://github.com/Ghostzy0/standby-pro.git
cd standby-pro
git checkout v1.1.0-preview.2
cd app
flutter pub get --enforce-lockfile
flutter analyze
flutter test
flutter build web --release \
  --base-href /standby-pro/demo/ \
  --no-web-resources-cdn

For a local static server, serve the web build at the same base path or rebuild with --base-href /. Keep generated build output out of app source commits.

Android and iPhone

Android native builds need JDK17 and a compatible Android SDK/Gradle. Configure your own release signing outside Git. The improved project no longer silently signs a release with a debug key.

iOS builds require macOS, Xcode, CocoaPods and signing for a physical iPhone. The current iOS target has no native display-control bridge or WidgetKit extension. Standby Pro does not replace Apple's system StandBy or promise always-on/lock-screen behaviour. App-local dimming works in the preview.

Install, update & remove

No APK or IPA is attached to this source preview. Download source and browser-preview archives only from GitHub releases and compare SHA256 with the supplied manifest. For a locally signed Android build, install via your normal trusted development workflow. A signing-identity change may require uninstalling the old build and losing its local settings. Never treat a debug build as a production update.

Existing v1 preferences retain their key. Invalid fields fall back to safe defaults. Weather is off by default when migrating an older preference file. To remove app data, uninstall the native app or clear the browser preview's site storage.

Acceptance still open

Physical Android and iPhone runs, TalkBack/VoiceOver, real battery/thermal/OLED behaviour, charger/lock-screen interactions and production signing are tracked in the device acceptance issue. Browser and widget evidence do not establish those results.
