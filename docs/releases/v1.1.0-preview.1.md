# Standby Pro1.1.0-preview.1

23 October2026 — improved **source and web preview**, separate from the preserved1.0.0 baseline. The existing repository/history/community and package ID remain. No production signed APK/IPA is supplied. Device/signing gates remain in issue#4.

## What changes

Display, Layouts, Timer and Settings navigation; About/data status; original four faces/themes; reversible Quiet display. Local visual focus sessions support presets, pause/reset and clear no-alarm/background limits. Readable scrolling settings and enlarged-text display avoid the overflow found by tests.

Weather is off by default, supports four public cities, validates actual current/daily fields and timezone offsets, labels source/time/failure and rejects stale responses. Calendar is explicitly sample data and audio metadata unavailable. No personal-data permissions are requested. Preferences migrate the original v1 key defensively and writes/errors/disposal are handled. Pixel shifts happen by minute and stop under reduced motion. Android keep-awake is accurately foreground-only; implicit debug release signing is removed.

Bundled licensed Roboto fonts fix the Google font request observed in the browser walkthrough. Original third-party listing reference captures are excluded from the new distribution; historical Git is preserved. Adds package notices, setup/privacy/FAQ, security/contribution guidance and static public docs.

## Reproduce and use

```sh
git clone https://github.com/Ghostzy0/standby-pro.git
cd standby-pro
git checkout v1.1.0-preview.1
cd app
flutter pub get --enforce-lockfile
flutter analyze
flutter test
flutter build web --release --base-href /standby-pro/demo/ --no-web-resources-cdn
```

Serve the built preview at `/standby-pro/demo/`; for another location rebuild with the matching base-href. The static preview archive has landing pages at its root and `demo/` beneath; mount its root at `/standby-pro/` or rebuild the Flutter demo for a different path. It is not double-click/file:// compatible. Use a local HTTP server or the public GitHub Pages site. SDK/package licences are included; regenerate notices after dependency changes.

For Android installable builds, add JDK17/compatible Android SDK and your own release signing outside Git. The current host has JDK17 but lacks a complete Android platform SDK in its build setup. iOS needs Xcode/CocoaPods and physical signing; no native iOS display-control bridge is implemented. No developer-account purchase or new signing/permission prompt was attempted.

## Update, uninstall and data

Preference key `standby_settings_v1` is retained; old/invalid fields fall back safely and weather remains off on migration. Baseline and improved native builds share package identity and are alternative builds. Changing signing identity may require uninstalling and lose settings. Uninstall the app or clear browser site storage to remove local preferences; closing resets the temporary focus session. Weather requests send public-city coordinates and IP to Open-Meteo, whose free endpoint is noncommercial. No paid fallback, analytics, account or ads.

## Remaining limitations

Physical Android/iPhone, production signing/update identity, VoiceOver/TalkBack, native keyboard/reduced-motion behaviour, charging/lock-screen/battery-saver, thermals and long-run OLED remain unaccepted. No Apple system StandBy/WidgetKit, real calendar/media metadata, automatic charging launch, background alarm, battery-life or burn-in guarantee. Arbitrary missing-glyph font fallback egress is outside the tested Latin UI path. Use24-hour default if you require an unambiguous visual period; the original12-hour face has no AM/PM ornament, while its semantic label includes the period.
